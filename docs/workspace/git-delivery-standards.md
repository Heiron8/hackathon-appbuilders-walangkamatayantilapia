# Git and Delivery Standards

- One meaningful task/change per branch/worktree by default.
- Stage related changes intentionally; do not blindly stage everything.
- Run verification before commit/push.
- Use logical commits with generated Conventional Commit messages.
- Link PRs to their GitHub issue/task.
- Independent review before merge according to risk policy.
- Main should remain stable; production release may have a separate gate from main/staging.

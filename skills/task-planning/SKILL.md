# Task Planning Skill

Convert approved architecture into small, reviewable implementation tasks with stable workspace task keys, module, acceptance criteria, dependencies, risk, Definition of Ready, and expected reviewers. Avoid tasks that mix unrelated concerns.

In `hackathon-24h` mode, prefer a small set of vertical slices prioritized P0 core journey, P1 credible supporting behavior, then P2 polish. Keep explicit ownership and real dependencies; avoid microscopic task publication and keep trivial same-scope corrections in the already-owned task.
